# placepin-about: working notes

`@placepin/about`. The documentation site for [placepin.org](https://placepin.org),
served at **about.placepin.org**. VitePress → static HTML → Cloudflare Pages.
No backend.

The protocol itself is in `../placepin-spec/SPEC.md`. The app is
`../placepin-web`. Read [`README.md`](./README.md) for how to run and deploy.

## The one structural rule

**This site renders the specification. It does not own it.**

`docs/spec/spec.md` is generated by `scripts/sync-spec.mjs` on every `dev` and
`build`, and it is gitignored. Editing it does nothing durable; the next build
overwrites it.

A hand-maintained second copy of a normative document is worse than no copy.
§10 requires that any change to what a code means be _visibly_ a version
change; a doc site quietly diverging from the spec is the invisible kind, and
there is no checksum anywhere in this protocol to catch the consequence.

If the spec needs changing, change it in `placepin-spec`.

## Rules that come from the specification, not from taste

These are the same rules `placepin-web/CLAUDE.md` carries. They apply to copy
here just as much as to behaviour there, arguably more, since this site is
where people learn what the rules are.

### A bare three-character string is a region, never a local block

§01, normative. Copy must never imply that "just the first block" gives a
coarser address. It gives nothing decodable at all. `TruncationLadder.vue`
shows the invalid rung deliberately: omitting it would let a reader infer the
symmetric rule that does not exist.

### Truncation runs right to left

`PYY-ZT7-WMR` → `ZT7-WMR` → `WMR`. Any diagram, table or sentence that shows it
the other way round is teaching the single most consequential error in the
protocol.

### There is no checksum

§06 ships no check character on purpose. Copy may not describe a code as
"verified", "validated" or "checked"; nothing checks it. Every corrupted code
is a valid address somewhere. Where this site describes building on placepin,
it must say the preview-and-confirm step out loud.

### Codes are not durable yet

§10: nothing before v5-final is durable, and §02 leaves `Y` unresolved. Copy
says "saved", never "forever", and the beta card says so explicitly. Do not
soften that line to make the call-to-action read better.

### No em dashes

Not in copy, not in comments. Split the sentence, or use a colon, comma,
semicolon or parentheses. The one exception is the synced `SPEC.md`, which
renders verbatim and whose dashes belong to another repository.

### Brand

Lowercase **placepin**, never "PlacePin". The wordmark is `placepin.org` with a
terracotta full stop and no pin icon (§07). In the nav bar the title is
`about.placepin.org`, rendered through VitePress's `siteTitle` as HTML so the
final stop can carry `--leaf`.

Codes render in Share Tech Mono, which ships **one weight**, so **every block
of a code is the same size** and hierarchy is carried by colour alone. The app
settled that in `CodeField.svelte`: a code with one enormous block in it reads
as a broken text field, not a headline.

`PinCode.vue` mirrors that component's `.code-metrics` (face, size,
letter-spacing, line-height), **not** the older `CodeDisplay.svelte`, which
still sizes the leading block larger. Where the two disagree, the field wins;
it is the code display a visitor recognises.

### `/next` is a plan, not the specification

`docs/next.md` describes intended direction: the 0.x-to-freeze road, and
non-Latin script support arriving with 1.0. None of it is in SPEC.md and none
of it is normative. Keep the banner at the top, and keep the open questions
marked **TODO** with who decides.

The non-Latin design is a **1:1 character mapping** onto the existing thirty,
which is what makes it safe to ship alongside a freeze: the grid is untouched,
a script code is the same address rather than a related one, and conformance
stays one vector suite. What is _not_ decided is every mapping table, and that
is deliberate. §02's "cannot spell a word" property does not automatically
survive being carried into another script, and only readers of that script can
say which of its characters are confusable. Do not fill those tables in.

## Design system

The palette is `placepin-web/src/lib/ui/tokens.css`, mirrored into
`docs/.vitepress/theme/tokens.css`. Two intentional differences, both forced by
the host:

1. Dark mode hangs off VitePress's `.dark` class, not `prefers-color-scheme`.
   The site has a theme switch and the switch has to win.
2. No `html, body` reset. VitePress owns document scroll, and
   `overscroll-behavior: none` on a document this long is hostile.

**When the app's palette changes, copy the token values across.** Everything
else is derived: `vitepress.css` re-points `--vp-*` at these tokens and invents
no colours of its own, so a palette edit needs no other change here.

### Why the theme extends rather than forks

The default theme already solves the tedious parts of a docs site (mobile
sidebar, outline, local search, anchor links, the appearance toggle) and none
of those carry placepin's identity. The identity is the palette, the two faces,
and how a code is drawn, all three reachable from CSS variables and six
components. A VitePress minor that reshuffles its internals still lands
correctly, because the theme reads variables rather than class names.

The three tier colours are load-bearing, not decorative: vermilion is always
the ≈5 m leaf, teal always the ≈840 m area, pale slate always the ≈137 km
region, on the map, in the lattice, and here. Terracotta stays out of general
chrome so it keeps meaning "most specific" wherever it turns up. Teal is the
interface accent.

## Traps

### `markdown.breaks` is on, so a wrapped line is a bug

SPEC.md is written with meaningful line breaks: the header block and every
normative blockquote put the label and the rule on separate lines, and
collapsing those into a run makes both read as neither. So `breaks: true`.

The cost lands on authored pages, where a hard-wrapped paragraph renders as a
stack of `<br>`s. It looks like a deliberate stanza and is nothing of the kind,
and the words are all still there, so it is easy to miss. **Write authored
prose unwrapped, one paragraph per line.** `sync-spec.mjs` checks this and
fails the build.

### The spec's anchors contain a middle dot

`## 03 · The grid` slugifies to `_03-·-the-grid`, underscore-prefixed because it
starts with a digit, and the `·` survives. `#_03-the-grid` looks right and
silently scrolls nowhere.

VitePress's dead-link check validates the _page_, not the anchor, so this
failure is invisible to it. `sync-spec.mjs` re-slugifies the real headings and
fails the build on a broken deep link. If that check ever starts producing
false positives, fix the slug rule to match `@mdit-vue/shared`. Do not delete
the check.

### The spec must be present at build time

`sync-spec.mjs` takes SPEC.md from a sibling `placepin-spec` checkout when
there is one, so local spec edits render before they are pushed, and otherwise
from the installed `@placepin/vectors`, which is the spec repo as a git
dependency and is what CI uses. That copy is pinned by the lockfile, so a spec
change reaches the site through `npm update @placepin/vectors`, deliberately,
not by whichever commit happened to be HEAD at deploy time. With neither
source the script exits non-zero: a build that cannot find the spec must fail
rather than ship a site whose entire reason for existing is a 404.

### `npm audit` reports findings that are not actionable

They are the esbuild dev-server advisory, transitive through VitePress 1.x, and
they affect the **development** server only, not the static output, which is
HTML and hashed assets. The fix is VitePress 2, which is not released. Do not
"resolve" this by pinning something that breaks the build.

## Addresses live in one place, with stated exceptions

`docs/.vitepress/theme/links.ts` holds every URL the site points at outside
itself: the org and its three repositories, `vectors.json`, `SPEC.md`, the beta
form, the app, and `hello@placepin.org`. `config.ts` and every component import
from it.

Four places cannot, and are listed here rather than left to be found:

| Place | Why |
|---|---|
| `docs/index.md` frontmatter | Markdown frontmatter is YAML; it cannot import |
| `docs/next.md`, the inline "Join the beta" link | Same |
| `docs/public/_redirects` | Cloudflare config, read by the CDN, not the build |
| `scripts/sync-spec.mjs` | Plain Node cannot import a `.ts` module, and adding a loader to save one string is the wrong trade |

Keep `BETA_FORM` equal to `placepin-web`'s `src/lib/app/AppShell.svelte`, which
links back here in return.

**`vectors.json` is linked, never hosted.** §03 makes the fixtures the
definition of conformance, so an implementer must test against the file in
`placepin-spec` that every implementation consumes, not against a copy this
site happens to be serving. `sync-spec.mjs` deliberately does not copy it in.

## The two faces come from Google Fonts, on purpose

`config.ts` links `fonts.googleapis.com` for Share Tech Mono and IBM Plex Mono.
This is a decision, not an oversight. Do not "fix" it by self-hosting.

The split is by artifact. **placepin.org is the offline one**: it has a service
worker, its whole argument is that it keeps working with no network, and it
vendors its own faces. **This is a documentation site.** Somebody reading a
specification has a network by definition, and sharing the CDN means a visitor
arriving from the app already has both faces cached.

The cost is worth stating rather than forgetting: a blocked or slow Google
Fonts degrades every placepin code to IBM Plex Mono, which looks fine on screen
and quietly loses the "this is an address" signal the type system exists to
carry. If that ever becomes the common case, self-hosting is ~63 KB of
latin/latin-ext woff2 and `placepin-web/scripts/vendor-fonts.mjs` already
fetches them.

## The inline-code rule

`config.ts` overrides markdown-it's `code_inline` renderer. Anything matching a
placepin code, **two or three hyphenated blocks** from the alphabet, is
re-emitted as tier-coloured spans in Share Tech Mono. Everything else stays in
IBM Plex Mono.

This exists because a CSS rule cannot tell `PYY-ZT7-WMR` from `placepin-spec`,
and the earlier one painted repo names, `decode()` and `FACTOR` in the address
face. Share Tech Mono means _this is an address_; spending it on everything in
backticks spends the signal.

**Bare three-character strings are deliberately excluded.** A lone block is the
most argued-over input in the specification: normatively it decodes as a region
(§01), but the prose around it is almost always discussing it _as a local
block_ to explain why that is not an address. Colouring it pale slate while the
sentence calls it local contradicts the sentence on screen. Authored pages use
`<PinCode>` where a tier is actually meant.
